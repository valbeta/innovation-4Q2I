# Lean 4Q2I Framework

## Purpose

Lean 4Q2I describes the minimum coherent system needed to move from opportunity recognition to value-system validation. **Lean** is the design principle: keep the core system minimal, coherent, and reusable while selecting supporting methods according to the uncertainty and evidence gap. **Innovation Value System Validation Framework** describes the purpose: organize evidence and decisions across four connected questions.

4Q2I is not a checklist requiring every project to use every available tool. Each stage has a core model, a minimum output, and a decision gate.

## Minimum system at a glance

| Question | Stage | Core model or framework | Minimum output | Decision gate |
|---|---|---|---|---|
| Q1 — Where do we stand? | Opportunity Recognition | Four 不 Matrix | Problem definition, current-state understanding, preliminary market/competitive view | Is the problem worth exploring? |
| Q2 — Where are we going? | Value-Creation Logic | C.O.R.E. | Value logic, value proposition, key assumptions, Q3 preparation | Is the value logic clear enough to validate? |
| Q3 — Who is with us — and why? | Stakeholder Validation | Three-Dimensional Desirability + Value–Resistance | Key-assumption findings, desirability assessment, iteration direction | Is there enough evidence to justify a market test? |
| Q4 — How do we get there? | Value-System Validation | Three-Dimensional Circuit-Breaker | Real-market feasibility findings and next investment decision | Can the value system operate sustainably? |

The stages form a sequence of gates, not a one-way waterfall. New evidence can require a return to an earlier question.

## Q1 — Opportunity Recognition

**Core uncertainty:** Have we identified a problem worth solving?

### Core model: Four 不 Matrix

The matrix characterizes the user's problem through four possible attributes:

- **避不开** — difficult to avoid;
- **等不及** — delay creates meaningful loss or urgency;
- **跟不上** — current experience or capability falls behind changing expectations or alternatives;
- **行不通** — existing approaches encounter feasibility, resource, or investment boundaries.

These attributes may coexist. Identify the dominant current problem state and explain the evidence behind the judgment. This is a user-problem model, not an analysis of the organization's resistance to developing a solution.

### Supporting methods

Choose environmental scanning, competitor analysis, the Eight-Dimension Competitive Advantage Model, JTBD, user research, or data analysis when they address a specific evidence gap. They are not mandatory sub-stages.

### Minimum output and gate

Produce a clear problem and target-user definition; current-state understanding that distinguishes evidence from assumptions; a preliminary view of market or competitive resistance; and a reasoned Four 不 Matrix judgment.

Proceed when the problem is sufficiently clear and there is evidence-based reason to explore it further. Proof of market size, solution superiority, or commercial viability is not required yet. Return to Q1 if new evidence changes the problem definition or the dominant problem state cannot be supported.

## Q2 — Value-Creation Logic

**Core uncertainty:** What value should be created, for whom, and through what logic?

### Core model: C.O.R.E.

- **Customer:** for whom is value created, and how do they obtain it?
- **Offering:** what carries and delivers the value?
- **Relationship:** how is value established, delivered, and sustained?
- **Experience:** how is value perceived and confirmed by the customer?

The dimensions interact. Use them to discover and clarify value levers, and redesign them when the current value logic is weak.

### Supporting method: Extreme Method

When key moments of truth (MOTs) are clear, the Extreme Method asks what it would mean to satisfy functional and emotional needs at those moments at an exceptionally high level. A clear MOT is a prerequisite; the method does not replace customer or core-value definition.

The emphasis varies by context. For experience iteration or process optimization, extreme exploration may receive more weight after core value and MOTs are clear. For product-logic or business-model reconstruction, C.O.R.E. generally plays the more central role.

### Conditional screening: Value–Resistance Model

This model compares user-perceived value with perceived costs and resistance to adoption. In Q2, it is a context-dependent design-screening judgment. Scores are qualitative and project-specific, not universally calibrated measurements.

### Minimum output and gate

Produce a coherent value-creation logic, an initial value proposition, explicit key assumptions selected for validation, and a Q3 validation preparation package. Proceed when the value logic can be clearly explained, assumptions are explicit, and a focused stakeholder-validation plan is ready. Assumptions may remain unproven. Return to Q2 when the value proposition is incoherent or evidence requires a different value-creation logic.

Value proposition design, customer journey and MOT mapping, scenario design, and causal-loop exploration may help clarify the logic or assumptions. Causal-loop analysis is optional.

## Q3 — Stakeholder Validation

**Core uncertainty:** Do relevant stakeholders recognize reasonable value and want to participate?

Q3 validates key assumptions carried over from Q2. Formal organizational approval is not a universal gate.

### Core evaluation framework: Three-Dimensional Desirability

1. **User desirability:** does the target user genuinely want the value?
2. **Operational desirability:** do delivery, support, operations, and relevant partners see sufficient value to participate?
3. **Business-model desirability:** does the proposed model offer a compelling rationale for the organization and other stakeholders?

Trade-offs may exist. Make them explicit rather than forcing artificial agreement.

### Shared analytical model: Value–Resistance

The Value–Resistance Model provides shared analytical logic across all three dimensions. The Three-Dimensional Desirability Model organizes validation questions and conclusions. They form one evaluation system, not three separate toolkits.

### Validation mechanism

Use a prototype or another suitable artifact to make the value proposition concrete enough to test. Choose interviews, tests, workshops, or other methods based on the assumptions being examined.

A shared validation record can include: dimension, key assumption, value hypothesis, resistance or objection, method and evidence, conclusion (supported, refuted, or insufficient evidence), and implication or adjustment. Evidence standards should fit each dimension.

### Minimum output and gate

Produce evidence-based conclusions for key assumptions, an assessment of all three desirability dimensions, explicit major resistance/conflicts/trade-offs, and an iteration direction with MVP validation preparation.

Proceed when assumptions have evidence-based conclusions, all three dimensions have been assessed, and issues capable of overturning the value proposition have been addressed or made explicit. Remaining uncertainty should be suitable for a controlled real-market test. Q3 does not prove market success or require formal budget approval in every context.

## Q4 — Value-System Validation

**Core uncertainty:** Can the value system operate sustainably in the real world?

### Core framework: Three-Dimensional Circuit-Breaker

Use small-scale real-market evidence to assess:

1. **Technical feasibility:** can the solution reliably deliver the promised value?
2. **Economic feasibility:** can the revenue and return loop support sustainable organizational returns and continued customer willingness to pay or buy?
3. **Operational feasibility:** can users adopt the solution and can the people and partners involved deliver and support it in practice?

Judge dimensions separately against context-specific standards. A critical failure means overall feasibility has not yet been established.

### MVP principle

MVP is not synonymous with a low-quality or feature-poor product. Its design is jointly determined by the **Minimum Viable Solution (MVS) value promise** for the target segment and the evidence required to assess the three feasibility dimensions across the C.O.R.E. value chain.

An MVP must sufficiently satisfy the target segment's core Jobs to carry the value promise and generate useful evidence. Feature count or visual polish alone is not a sufficient design criterion.

### Minimum output and gate

Produce three-dimensional feasibility findings grounded in real-market evidence, an MVP iteration plan, a market-entry/adoption/delivery-support plan, and a business-model sustainability judgment with a next investment decision.

Further investment is justified when each critical dimension meets the relevant standard and the feedback loop is functioning. A small-scale launch does not automatically prove scalability. If evidence fails, return to the stage that owns the uncertainty: Q2 for value logic, Q3 for stakeholder desirability, or Q4 for implementation and delivery issues. Stop or reduce investment when continued testing has no credible basis.

MVP, GTM, On-ramp, onboarding, business-model validation, and operational data are supporting methods selected according to the evidence needed.

## Cross-stage principles

### Evidence before escalation
Each stage must produce enough evidence to justify the next kind of investment. A gate is a decision rule, not a claim of certainty.

### Distinguish uncertainty types
- Q1: Is the problem worth exploring?
- Q2: Is the value-creation logic coherent?
- Q3: Do relevant stakeholders want to participate?
- Q4: Can the value system operate sustainably in a real setting?

### Use tools selectively
The core model organizes the work. Supporting methods should address a defined uncertainty or evidence gap, not be included simply because they are available.

### Iterate when evidence changes
The sequence provides discipline; feedback provides adaptation. Returning to an earlier question is appropriate when new evidence changes a premise or invalidates a conclusion.

### Treat models as aids to judgment
Project context matters. Qualitative assessments, thresholds, and evidence standards should not be presented as universally calibrated unless empirically established for that use.
